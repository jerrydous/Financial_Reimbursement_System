# AGENTS

本文件是实现 AI 的执行入口。详细规则在 `docs/`，冲突时以本文件的停机条件为准，其余细节以对应文档为准。

## 必读

1. `docs/technical-plan.md`
2. `docs/quality-gates.md`
3. `docs/prohibitions.md`
4. `docs/positive-requirements.md`

未读完不得写业务代码。

## 构建方法

设计自顶向下：先守住目标基线、限界上下文、状态机、金额不变量和验收标准。

拆分用分而治之：按业务能力做垂直切片。每一片同时交付契约、表结构、API、页面和测试。

实现阶段的自底向上只表示接通顺序：先把身份、数据库、对象存储、工作流、规则引擎跑通一条冒烟路径，再编排进业务单据。这些能力使用成熟产品，不在本仓库重新实现。

禁止先自研日志、权限、表单引擎、流程引擎、消息总线，再指望业务能拼起来。

## 当前目标

单企业、单账套的费控闭环。金额以整数「分」为事实。同一张有效发票不能进入两张有效报销单。审批、驳回、撤回、支付可追溯。

本阶段不做：多租户计费、税局勾选认证、自研 OCR、自研会计引擎、自研 BPM、商旅自动下单、手写签名、信用分抽审、Kubernetes、按服务拆仓。表上保留 `tenant_id`，默认一个租户。

## 切片顺序

只实现当前切片。未通过 `docs/quality-gates.md` 不得开始下一片。

| 切片 | 完成标准 |
|---|---|
| P0 骨架 | Compose、Keycloak 登录、员工与公司抬头、空报销列表、CI、`.env.example`。未登录被拒绝；登录后只看到自己的员工身份 |
| P1 对私闭环 | 上传发票、OCR 草稿、人工确认、报销单、单线审批、财务改批准金额、出纳确认支付、审计。重复提交不产生第二张单；支付成功后金额不可改 |
| P2 费控 | 申请额度、差标强弱控、补贴、借款与冲销、逾期未还拦截 |
| P3 审批 | 会签、或签、条件分支、代理、转交、撤回、超时提醒 |
| P4 分摊与预算 | 多维预算的冻结、消耗、释放。并发不能把预算行打成负数 |
| P5 发票合规与台账 | 验真、抬头税号、类型/时间/金额匹配、及时性、导出台账 |
| P6 对公与外部系统 | 到票付款、凭证导出适配器、商旅订单导入适配器 |

P0 第一批文件：仓库骨架、Compose、契约包、Keycloak 登录、员工只读 API、一条失败即红的金额单测、README 启动步骤。这条冒烟路径变绿之前，不写报销单页面。

## 执行顺序

1. 把上述文档当作目标基线。发现矛盾就停，要求人工发新版本。不得在编码时悄悄扩大范围。
2. 每个能力先核对官方 SDK 的真实方法，再写适配器。
3. 先写失败测试，再写领域代码，再接数据库和页面。
4. 运行质量门禁命令。禁止改测试去迁就错误金额。
5. 独立审查按 BLOCK / WARN / PASS 给出结论。
6. 通过后提交该切片。只有用户明确要求时才提交或推送。

## 停机条件

出现下列任一情况，停止写代码并说明原因：

- 需要的业务规则没有书面来源，例如税率、差标、审批层级。
- 准备自研认证、流程引擎、规则引擎、OCR、查验、对象存储或表格格式。
- 准备用 JavaScript `Number` 或浮点运算金额。
- 准备把 Mock、假 OCR 或「未验真」标成验真通过。
- 质量门禁命令失败。
- 偏离 `docs/technical-plan.md` 的技术栈，且没有 `docs/adr/` 偏离说明。
