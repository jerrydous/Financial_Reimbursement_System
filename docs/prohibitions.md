# 禁止清单

三池同时生效。A 与 B 收自功法质量门禁里适用于本系统的条目。C 是财务约束。

数值计算、NumPy、pandas、GPU、PyTorch 的禁止项不进入本仓库规则，避免实现跑去建数据科学项目。

## A. 胶水与完整性

```text
禁止自行实现认证、令牌、权限引擎、流程引擎、规则引擎、OCR、发票查验、对象存储、表格格式、消息投递
禁止把依赖库复制进仓库再改
禁止裁剪、重写或用简化版冒充 Keycloak、Temporal、Prisma、Ant Design、官方 OCR SDK
禁止 Mock、Stub、空实现、假 OCR 结果进入生产模块
禁止只导入不调用的伪集成
禁止路径遮蔽或 fallback 到测试替身
禁止在领域包重写依赖库已有算法
禁止用代码行数评价方案
禁止未写偏离说明就自研核心能力
```

测试可以在端口边界替换外部 IO。被测的金额、状态、预算、核销规则必须跑真实领域代码。

## B. 工程、验证与伪性能

```text
禁止把“代码更短”误判为“性能更好”
禁止把用了 async、队列、缓存、批处理、框架默认参数误判为已经高性能
禁止把能跑通样例、小数据很快、单次计时很快外推为系统合格
禁止没有基线、没有输入规模、没有正确性回归就声称性能提升
禁止没有定位瓶颈就重写热路径
禁止牺牲正确性、可审计性或幂等换表面速度

禁止 ORM 循环访问关联造成 N+1
禁止循环里逐条 insert 或每次 commit
禁止查出整表再在内存过滤
禁止列表没有分页
禁止用很大的 offset 做深分页而不评估键集分页
禁止事务里调用 OCR、查验、通知等外部网络
禁止长事务占着预算行的锁
禁止无超时的外部请求
禁止无限重试；禁止对支付确认做无幂等重试
禁止无上限并发打外部查验或 OCR

禁止无失效策略的全局缓存
禁止缓存用户票据、发票影像或跨员工的报销数据
禁止把 Redis 锁当成预算或余额的真相

禁止吞掉异常或用空 catch
禁止用 null、undefined、false 混作业务错误
禁止同一金额在报销单、费用行、预算、付款单各写一份且互不约束
禁止跨请求共享可变对象
禁止猜 API、编造库、编造税率和差标
禁止扩大修改范围、顺手重构、未理解既有设计就改结构
禁止跳过测试仍声称完成
禁止伪造命令输出、CI 通过或外部接口成功
禁止架构变了却不改 README 和 AGENTS
```

总原则：

```text
禁止任何“看起来更短、更高级、用了异步或缓存，但没有复杂度说明、测量基线和正确性回归”的修改进入报销热路径。
```

## C. 财务与报销

```text
禁止用 JavaScript Number 或二进制浮点存储、相加、比较金额
禁止在客户端算出最终批准金额、预算占用或可付金额再让服务端信任
禁止先 select 发票再 insert 来实现查重
禁止支付成功后覆盖原始金额、发票或审批记录
禁止物理删除报销单、申请单、借款单、付款单、审计记录
禁止财务调整不保留调整前的值
禁止无 Idempotency-Key 的提交、冻结和支付接口
禁止驳回、撤回、支付失败时忘记释放预算冻结
禁止或签被实现成会签，或会签在一人通过后直接结束
禁止代理人获得被代理人以外的数据范围
禁止员工读取他人报销单、发票影像和银行卡
禁止日志、错误响应、前端埋点打印完整身份证号、银行卡号、税号以外的密钥
禁止把智能审核模型的自由文本当作可过账结论
禁止在未接通官方查验 API 时把发票标成“已验真”
禁止用删除发票行绕过重复报销
```
