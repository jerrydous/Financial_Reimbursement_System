# 质量门禁

AI 的口头「已完成」无效。能变成测试、类型、lint、CI 或数据库约束的规则，不要只写在提示词里。

## 表达层

- 当前切片的目标、不做事项、验收命令写在该切片的任务说明里。
- 业务规则没有书面来源时，停下来标成假设，不得编造税率、差标或审批层级。
- 使用了自研替代成熟库时，仓库里必须有 `docs/adr/` 偏离记录。

## 结构层

- 新代码落在 `docs/technical-plan.md` 的目录中，领域包不出现 IO。
- 外部 SDK 类型停在 `packages/adapters`。
- 一个职责一个入口。禁止再写一套平行的报销服务或第二套金额工具。
- 架构或目录变化时，同时改 README 和 AGENTS。

## 执行层

- `docker compose up` 后，API、Worker、Temporal、PostgreSQL、Redis、MinIO、Keycloak 全部健康。
- 迁移只向前新增。禁止改已经合并的迁移文件。
- `.env` 不入库。密钥扫描必须通过。

## 验证层

最低命令：

```bash
pnpm typecheck
pnpm lint
pnpm test
pnpm test:integration
pnpm audit --prod
```

必须存在的机器断言：

- 领域单测覆盖状态机、尾差、冲销、发票唯一、预算不能为负。
- 集成测试使用 Testcontainers 的真实 PostgreSQL，覆盖幂等和 `FOR UPDATE`。
- 契约测试锁定 Zod 与 OpenAPI 一致。
- 金额类型测试拒绝 `number` 字段。
- Playwright 覆盖 P1 主路径。P0 阶段改为覆盖登录与员工身份。
- 列表接口没有分页则测试失败。
- 对外部 HTTP 的生产代码没有超时则测试或 lint 失败。

P1 之后的性能门禁只测三条路径，并保留基线：报销单列表分页、提交事务、预算并发 20 个请求。报告 p95、错误数和数据库查询数。没有基线不得声称变快。

## 交付层

- `git diff` 里没有无关重构、示例密钥、发票影像和 `.env`。
- 每个切片一次可回滚提交。提交说明写清为什么。只有用户明确要求时才执行提交或推送。
- CI 红则继续修，禁止把失败解释成环境问题后结束任务。
- 独立审查按 BLOCK / WARN / PASS：目标是否达成、禁止池是否违反、证据是否可复跑、是否越界改动。

## 审查单

审查者单独阅读原始规格和 diff，不沿用实现者的结论。输出：

```text
结论：BLOCK | WARN | PASS
目标：当前切片是否达成
禁止池：违反了哪一条，或无
证据：命令、退出码、失败用例
越界：无关改动、秘密、范围膨胀
```
