# 财务报销系统

单企业、单账套的费控系统。员工提交对私报销，经过发票确认、主管审批、财务审核和出纳支付，留下不能改写的审计记录。金额以整数「分」记账，页面上显示为元。

当前可用路径：登录、发票账本、腾讯云增值税发票识别、人工确认、提交报销、主管审批、财务修改批准金额、出纳确认支付。另外可以提交事前申请和借款、按制度和补贴校验报销、冻结预算、会签或或签、设置审批代理、查验发票、导出台账、登记对公付款、导入商旅订单、导出已支付凭证。没有配置查验密钥时，发票保持「未验真」，不会显示验真通过。

目录、配置和测试说明见 [docs/guide.md](docs/guide.md)。

## 使用说明

### 启动

```bash
cp .env.example .env
docker compose up --build
```

浏览器打开 http://localhost:5173 。

| 服务 | 地址 |
|---|---|
| 网页 | http://localhost:5173 |
| API | http://localhost:3000 |
| Keycloak | http://localhost:8088 |
| MinIO 控制台 | http://localhost:9001 |

本地开发账号的口令与账号相同，只用于本机：

| 账号 | 岗位 |
|---|---|
| employee1 | 员工 |
| manager1 | 主管 |
| finance1 | 财务 |
| cashier1 | 出纳 |

未登录不能查看报销单。登录后只能看到自己的员工身份和公司抬头。

### 提交一张报销单

1. 用员工账号登录，打开「我的账本」→「新建费用」。
2. 上传发票影像（PDF、JPEG 或 PNG）。配置了 `OCR_PROVIDER=tencent` 和腾讯云密钥后，系统会填入发票代码、号码、价税合计、销售方和开票日期。未配置时请手工填写。核对后点「确认发票」。验真状态仍是「未验真」。
3. 在「未报销」里勾选发票，点「创建报销单」。申请单、借款单、合同、分期、还款和付款单在「我的单据」里切换。事前申请批准后，报销不能超过剩余额度。借款逾期未还会拦住新的报销。
4. 主管在「待我处理」中同意或驳回。会签要全员通过，或签一人通过即可。代理期间由代理人操作。财务审核中可以修改批准金额，原始提交金额仍保留。出纳确认支付。选了预算行时，提交冻结预算，驳回或撤回释放，支付后转为消耗。
5. 单据详情可以按短时链接查看发票影像，并看到每次提交、审批、调整、支付和弱控警告。单笔超过 1000.00 元会留下警告，超过 5000.00 元不能提交。已确认发票可以查验；未配置腾讯云查验时状态仍是未验真。账本可以导出。已支付单据可以导出凭证报文。

员工在主管通过之前可以撤回。驳回或撤回后可以改回草稿再提交。同一张已确认发票不能同时进入两张有效报销单。支付成功后金额不能再改。

## 系统架构

网页、接口和审批工作进程分开部署，共用同一套契约和领域规则。

```text
浏览器
  │  Keycloak 登录
  ▼
apps/web          Vite + React + Ant Design
  │  HTTP，金额用字符串传递「分」
  ▼
apps/api          NestJS。鉴权、事务、单据接口
  │                 ├── PostgreSQL 16（Prisma）：单据、发票、审计
  │                 ├── MinIO：发票影像
  │                 └── Redis：幂等加速，不作为金额依据
  ▼
apps/worker       Temporal Worker。审批等待与状态推进
```

| 目录 | 职责 |
|---|---|
| `apps/web` | 页面。不访问数据库，不持有对象存储密钥 |
| `apps/api` | HTTP、事务和鉴权。不在请求里长时间等待审批 |
| `apps/worker` | 审批流程的等待、同意、驳回和支付推进 |
| `packages/contracts` | 前后端共用的请求和响应契约 |
| `packages/domain` | 状态迁移、金额和发票占用规则。不访问网络和数据库 |
| `packages/adapters` | Keycloak、Temporal、对象存储、腾讯云识票和数据范围的接入 |

依赖方向：网页只依赖契约；接口和工作进程依赖领域、契约和适配器；领域包不依赖 Web 框架、数据库客户端和工作流 SDK。

身份由 Keycloak 签发。接口把外部身份映射到员工，再用数据范围限制本人、主管、财务和出纳能看到的单据。发票影像存在 MinIO，浏览器只拿到短时查看地址。

### 报销单状态

```text
草稿 → 已提交 → 主管审批 → 财务审核 → 待支付 → 已支付
                  │            │
                  ├─ 驳回       └─ 驳回
                  └─ 撤回
```

驳回和撤回可以回到草稿。财务调整只发生在财务审核，并单独留下调整前后的金额。已支付、驳回、撤回都不做物理删除。

### 金额

数据库里的金额是整数分。接口用字符串传输，避免二进制浮点。报销单金额等于费用行合计。创建报销单和确认支付都带幂等键，重复请求返回第一次的结果。审计记录只追加。

更细的数据边界和后续阶段见 [docs/technical-plan.md](docs/technical-plan.md)。
